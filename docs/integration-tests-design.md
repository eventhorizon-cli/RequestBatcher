# Integration Test Environment Design

## Contract

The observability integration test project remains under `tests/it`. Its live container test is opt-in through
`REQUESTBATCHER_RUN_INTEGRATION_TESTS=1`; in-process stress tests run without the switch. When enabled, the test fixture owns the complete
environment required by the live test: a PostgreSQL 17.6 database seeded with the sample
products, an OTEL-LGTM 0.29.0 backend, and the Cart and Pricing images built from the sample
Dockerfile. The fixture exposes only the host URLs needed by the test process.

When the switch is absent, the live tests are skipped and no Docker resource is created. The
sample's Compose workflow remains available for people inspecting the sample manually; it is not
used by the automated integration project.

## Internal flow

The fixture creates one random Testcontainers network per test run and attaches PostgreSQL,
LGTM, Pricing, and Cart with stable network aliases. It builds the two application images from
the repository Dockerfile, starts dependencies in order, waits for health endpoints, then exposes
random host ports for Cart and Grafana. The test sends requests through those mapped host ports
and queries Grafana's provisioned Tempo and Prometheus proxies.

The fixture owns startup failure reporting and captures container logs when startup fails. Cleanup
is registered through Testcontainers' resource reaper and is also performed explicitly in
`DisposeAsync`; partial startup and cancellation use the same cleanup path. The fixture never
creates a nested service provider or changes sample runtime behavior.
Startup has a ten-minute deadline and individual readiness checks have two-minute deadlines. PostgreSQL readiness
requires its TCP listener and `pg_isready`, so its temporary initialization server cannot signal readiness before
the seed script finishes. Cleanup attempts every owned resource and reports aggregate failures.

## Compatibility impact

The public library and sample Compose contract are unchanged. The integration test no longer
accepts fixed `REQUESTBATCHER_CART_URL` or `REQUESTBATCHER_GRAFANA_URL` overrides because those
addresses are generated by the fixture. The opt-in environment variable remains compatible.

## Test coverage

The existing live test continues to verify response correctness, span parentage and both explicit link directions
(`Handle` -> contributing `Execute`, and `Execute` -> handled `Handle`), batch boundaries, and all five exported metrics. Its assertions now run against the
fixture-owned environment. A separate non-Docker tracing stress test can run with the normal test
suite and does not depend on this fixture.
The database child is identified by Npgsql's `db.query.text` attribute. A cold connection pool may also emit a
physical connection span under the same HTTP server; it is not counted as a second SQL query.

The stress tests use the public API and real OpenTelemetry SDK. At 0% and 100% sampling, each runs 32 waves of
512 requests with mixed single and 16-item submissions, bounded capacity, and an asynchronous handler. Every
request must complete exactly once. Recorded `Handle` -> `Execute` and `Execute` -> `Handle` links must match actual handler membership,
with no duplicate, parent, or previous-wave links. Capture is cleared after validating each wave. A coordinated
case checks queued cancellation, original handler failure identity, disposal draining, and rejection of late work;
its gate is released in `finally` and cleanup waits are bounded.

Coverlet collects the `RequestBatcher` production assembly inside the test host. This measures in-process stress
coverage; the external sample containers are not instrumented by that collector. The existing integration CI job
uploads its report with the `integration` Codecov flag; unit reports use `unit`. Tests continue to own their container
lifecycle, with no Compose startup or cleanup steps in CI.
